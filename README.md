# Доработка платформы программных соревнований

Проект выполнен на основе готовой платформы DevSec Contest_01. Исходная основа уже включала регистрацию участников, три задачи, проверку ответов, таблицу лидеров и таймер соревнования. Ниже описаны доработки этой основы.

## Редактор кода

- Встроен Monaco Editor с выбором Go, Python и C#.
- Рабочая область разделена на две части: условие задачи слева, большой редактор справа.
- Добавлены начальные шаблоны программ, скачивание кода и примеры чтения `input.txt` и создания файла ответа `stdout`.
- Реализованы подсказки, диагностика и автоимпорты через языковые серверы gopls, python-lsp-server и csharp-ls.
- Частые функции стандартных библиотек доступны в локальных подсказках, пока сервер подготавливает проект; серверные результаты подгружаются в фоне.

## Черновики и история

- Код и выбранный язык сохраняются автоматически и восстанавливаются после обновления страницы.
- Версии черновика защищают от перезаписи устаревшим сохранением: при конфликте сервер возвращает HTTP 409.
- Каждое успешное сохранение создаёт снимок в истории. Черновик и снимок записываются в одной транзакции.
- В панели преподавателя можно найти студента по ФИО и просматривать хронологию написания кода ползунком.

## Выполнение и проверка решений

- Добавлена кнопка «Выполнить и проверить» для Go, Python и C#.
- Программе доступны входной файл `input.txt`, файл с именем задачи и стандартный ввод.
- Ответ читается из обычного файла `stdout`; если файл не создан, используется стандартный вывод программы.
- Результат сравнивается с ожидаемым ответом задачи; правильное решение получает баллы.
- Вывод программы и ошибки доступны в левой панели рядом с условием задачи.
- Обрабатываются ошибки компиляции, выполнения, превышение времени и объёма вывода.

## Изоляция и ограничения

- Выполнение программ и работа анализаторов вынесены в отдельные сервисы. Публичный backend не получает доступ к Docker.
- Пользовательский код запускается в контейнерах с обязательным gVisor (`runsc`), без сети и с ограничениями CPU, памяти, процессов и файлов.
- Контейнеры работают от непривилегированного пользователя, с корневой файловой системой только для чтения и без дополнительных capabilities.
- Для участников используются отдельные среды анализа. Количество контейнеров и ожидающих запросов ограничено; добавлена очередь с освобождением неактивных сессий.
- Ускорены запуск компиляторов и подготовка анализаторов: используются заранее подготовленные доверенные кэши и предварительная компиляция C#-компонентов.

## Панель преподавателя

- Добавлены история кода, поиск участника по ФИО и просмотр сохранённых версий.
- Фиксируются копирование, вставка, уход со вкладки и возвращение на неё.
- Показывается время, затраченное на задачу: от первого выбора до первого правильного решения. Это прошедшее время, включая перерывы.
- Запросы событий ограничены по частоте; повторная отправка одного события не создаёт дубликаты.

## Запуск и проверка

- Добавлен локальный запуск сервисов одной командой через `scripts/dev.sh`, включая режим работы через маршрутизатор: `./scripts/dev.sh start --lan`.
- Доработаны миграции PostgreSQL и запросы sqlc для черновиков, истории, событий и запусков.
- Добавлены проверки runner, подсказок и нагрузки: `check-runner`, `check-assist`, `check-load`.
- Проведён десятиминутный API-прогон на 25 участниках: 7475 сохранений, 1475 проверок восстановления, 250 периодических запусков; ошибок не обнаружено. Все 7525 версий истории сохранены, финальные правильные решения всех 25 участников получили баллы.
- Проверены восстановление после перезапуска и доступ через локальную сеть. Нагрузочный прогон проверяет API и настоящие контейнеры, а не эмулирует браузеры или Wi-Fi.

**Известное ограничение:** при одновременном подключении всей группы полный анализ проекта и первые серверные подсказки могут занимать около 27 секунд. Локальные подсказки стандартных функций доступны во время ожидания.
